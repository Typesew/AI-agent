# Банковский переводчик

Локальный ИИ-агент, который объясняет простым языком условия кредитных и дебетовых карт,
рассрочек и студенческих карт и находит подводные камни. Векторный RAG и граф знаний
отвечают на вопросы по условиям, детерминированные MCP-инструменты считают платежи и даты,
а вопросы вне темы агент вежливо отклоняет.

**Учебный проект.** Пять банков и 20 продуктов вымышлены, все документы помечены
«учебный документ, не оферта». Совпадения с реальными продуктами случайны.

Всё работает локально: Ollama (`qwen3:8b`, эмбеддинги `bge-m3`), Chroma, Kuzu, Streamlit. Облачных API нет.

## Запуск

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
ollama pull qwen3:8b && ollama pull bge-m3
.venv/bin/python -m corpus.build_corpus          # YAML -> data/raw/*.md, эталонный граф, каталог
.venv/bin/python -m indexing.embed_index         # чанки -> bge-m3 -> Chroma
.venv/bin/python -m indexing.build_graph         # эталонный граф -> Kuzu
.venv/bin/python -m unittest discover -s tests -t .
.venv/bin/python -m eval.run_eval --llm          # 20 вопросов с Qwen3 (без --llm — офлайн-проверка)
.venv/bin/streamlit run ui/app.py                # http://localhost:8501, MCP-сервер стартует подпроцессом
```

Без Ollama:
- `python -m indexing.embed_index --embedder hash` строит индекс на лексической заглушке, только для проверки обвязки;
- поиск работает, а ответы LLM нет: интерфейс покажет понятную ошибку;
- если индекса Chroma нет, ретривер переходит на чистый BM25 и предупреждает об этом.

Дополнительно:

```bash
.venv/bin/python ask.py --demo --mermaid         # графовый путь без LLM, цепочки в Mermaid для слайдов
.venv/bin/python -m eval.run_eval --no-graph     # тот же прогон без графа: сравнение для защиты
.venv/bin/python -m indexing.extract_llm         # LLM-экстракция графа (Ollama)
.venv/bin/python -m eval.eval_extraction         # P/R/F1 LLM-графа против эталона
.venv/bin/python -m indexing.build_graph --source llm
```

## Как устроено

```
вопрос -> rag/entities.py (банк, продукт, тип, термины, события)
       -> agent/router.py (Qwen3, JSON: rag | tool | both | refuse; аргументы проверяет код)
       -> agent/client.py -> mcp_server/server.py (FastMCP, stdio)   — расчёты
       -> rag/retriever.py: vector_retriever (Chroma + BM25 + RRF) + graph_retriever (Kuzu)
       -> rag/prompt.py (фрагменты [c1], факты [f1], расчёты [t1]) -> Qwen3
       -> ответ «Плюсы / Минусы / Подводные камни / Итог» + блок «Источники» (собирает код)
```

| Путь | Что делает |
|---|---|
| `corpus/products/*.yaml` | единственный источник истины по 20 продуктам: текст пункта и узел графа рядом |
| `corpus/glossary.yaml` | 34 термина и 10 событий с алиасами для поиска в вопросе |
| `corpus/extra/*.md` | 6 памяток и 8 разборов кейсов (только векторный индекс) |
| `corpus/build_corpus.py` | YAML -> `data/raw/*.md`, `data/extracted/gold/*.json`, `data/catalog.json` |
| `indexing/schema.py` | схема графа, DDL, проверка связей |
| `indexing/chunk.py` | чанкинг по разделам, пункт договора не режется |
| `indexing/embed_index.py` | эмбеддинги через Ollama `/api/embed` -> Chroma |
| `indexing/build_graph.py` | gold/llm-разметка -> Kuzu |
| `indexing/extract_llm.py` | экстракция по жёсткой схеме (Ollama structured output) |
| `rag/graph_store.py` | **весь Cypher и работа с Kuzu**: перенос в другую графовую БД — правка одного файла |
| `rag/entities.py`, `rag/text.py` | распознавание сущностей и правила неоднозначности |
| `rag/vector_retriever.py` | Chroma + собственный BM25 + RRF, фильтры по метаданным |
| `rag/graph_retriever.py` | обход на 1–2 хопа, сравнение, DOT и Mermaid |
| `rag/prompt.py` | промпт и разбор строки `ИСПОЛЬЗОВАНО` |
| `mcp_server/` | `loan_calculator`, `grace_period_calc`, `compare_products`, `save_summary` |
| `agent/` | маршрутизатор, MCP-клиент, агент |
| `ui/app.py` | Streamlit: чат, источники, «Показать расчёт», «Цепочка в графе», переключатель графа |
| `eval/` | 20 вопросов, прогон, оценка экстракции |
| `docs/demo.md` | чек-лист демонстрации |

### Граф

Узлы: Bank, Product, Condition, Fee, Exception, Event, Term, Document.
Связи: OFFERED_BY, HAS_CONDITION, CHARGES, HAS_EXCEPTION, CANCELS, DEFINED_AS, SOURCE и два расширения:
- `TRIGGERS` (Event → Fee/Condition): пропуск платежа ничего не отменяет, а включает штраф или новую ставку;
- `APPLIES_TO` (Exception → Event): «снятие сверх 50 000 ₽ не входит в грейс» относится к превышению лимита, а не к снятию наличных.

У каждой связи есть `section`: пункт документа, где она написана. Поэтому ссылка ведёт
на «2.4. При пропуске платежа грейс отменяется», а не на «2.1. Льготный период — до 120 дней».

### Инструменты

Все расчёты детерминированные и выполняются кодом.
- `loan_calculator(sum, rate, months, type, fee)`: аннуитет `P = S·r / (1 − (1+r)^(−n))`, при `rate = 0` платёж `S/n`;
  для дифференцированных платежей переплата `S·r·(n+1)/2`.
- `grace_period_calc(purchase_date, statement_day, grace_days, mode)`: период из N дней включает дату старта,
  последний день = старт + N − 1. Режимы: `from_purchase`, `from_month_start` («Полярная 120»),
  `base_plus_extension` («Меридиан 150»: 60 + 90 дней).
- `compare_products(ids)`: таблица из графа по обслуживанию, снятию наличных, грейсу и кэшбэку.
- `save_summary(title, text)`: файл в `data/summaries/`; имя санитизируется, выйти из папки нельзя.

Параметры грейса берутся из каталога продукта, а не у модели. Числа для `loan_calculator`
обязаны встречаться в вопросе, иначе агент задаёт уточняющий вопрос.

### Маршрутизация и отказы

- Вопрос без слов предметной области и без чисел («какая погода завтра») отклоняется без вызова LLM.
- Банковская тема, которой нет в корпусе (вклады, ипотека), получает ответ «В корпусе нет данных по этому вопросу.»
- Остальное решает маршрутизатор. Расчётные вопросы без продуктов («кредит 100 000 ₽ под 18%») не отклоняются.
  Если маршрутизатор предлагает отказ, но в вопросе есть продукты, термины или числа, или если его ответ не разобран, агент откатывается на `rag`.

## Оценка

`eval/questions.json`: 20 вопросов с чек-листом фактов, ожидаемыми источниками, инструментом и числами.
Текст ответа дословно не сравнивается.

| Режим | Что проверяет | Результат |
|---|---|---|
| `run_eval` (офлайн) | всё, кроме формулировок LLM: маршрут — эталонный, «ответ» — собранный контекст | 20/20 |
| `run_eval --no-graph` (офлайн) | то же без графа | 17/20: падают cross-product вопросы 4, 5, 9 |
| `run_eval --llm` | реальный Qwen3 | **не запускался**: в среде разработки нет Ollama |
| `eval_extraction` | F1 LLM-графа против эталона | **не измерен**: нет Ollama; на эталоне 1.00 (проверка метрики) |

Офлайн-результаты получены на хеш-эмбеддингах, а не на `bge-m3`. После `ollama pull bge-m3`
и `python -m indexing.embed_index` их нужно перепроверить.

## Риски

- **Качество LLM-экстракции.** Qwen3 8B может путать «отменяет» и «влечёт» или терять исключения. Порог: F1 ≥ 0,7.
  Если ниже, для демо остаётся эталонный граф из YAML, а на защите показываются оба значения.
  На шаблонных документах F1 завышен, поэтому 7 документов (минимум один на банк) написаны свободным стилем.
- **Kuzu архивирован.** Версия закреплена (`kuzu==0.11.3`), весь Cypher изолирован в `rag/graph_store.py`.
- **Модель 7–8B и инструменты.** Поэтому инструментов 4, вместо function calling используется JSON-маршрутизатор с плоскими полями,
  а аргументы проверяет код.
- **Неоднозначность названий** (банк или продукт, «100 дней» или «за 100 дней»): правила в `rag/entities.py`, тесты в `tests/test_entities.py`.
- **Условия вымышлены.** В интерфейсе постоянная пометка, в каждом источнике дата редакции.
- **Названия программ лояльности** («Спасибо», «ЯРКО») и продукта «100 дней» взяты из постановки задачи.
  Если на защите они нежелательны, их можно переименовать в YAML и перегенерировать корпус одной командой.

## Проверка, что старых банков нет

```bash
grep -rniIE "полярн|сирень|каштан|polar|siren|kashtan" . --exclude-dir=.venv --exclude-dir=chroma | grep -viE "полярная 120"
```

Команда ничего не выводит. Единственное допустимое совпадение — «Полярная 120», продукт банка «Северный Путь».
Ту же проверку делает тест `tests/test_corpus.py::test_no_old_banks`.
