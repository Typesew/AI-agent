# Банковский переводчик

Локальный ИИ-агент, который объясняет простым языком условия кредитных и дебетовых карт,
рассрочек и студенческих карт и находит подводные камни. Векторный RAG и граф знаний
отвечают на вопросы по условиям, детерминированные MCP-инструменты считают платежи и даты,
а вопросы вне темы агент вежливо отклоняет.

**Учебный проект.** Пять банков и 20 продуктов вымышлены, все документы помечены
«учебный документ, не оферта». Совпадения с реальными продуктами случайны.

Всё работает локально: Ollama (`qwen3:8b`, эмбеддинги `bge-m3`), Chroma, Kuzu, Streamlit. Облачных API нет.

## Запуск

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
ollama pull qwen3:8b && ollama pull bge-m3
# Ollama на Windows, проект в WSL2: адрес хоста (Ollama запущен с OLLAMA_HOST=0.0.0.0:11434)
export OLLAMA_URL=http://$(ip route show default | awk '{print $3}'):11434
.venv/bin/python -m corpus.build_corpus          # YAML -> data/raw/*.md, эталонный граф, каталог
.venv/bin/python -m indexing.embed_index         # чанки -> bge-m3 -> Chroma
.venv/bin/python -m indexing.build_graph         # эталонный граф -> Kuzu
.venv/bin/python -m unittest discover -s tests -t .
.venv/bin/python -m eval.run_eval --llm          # 20 вопросов с Qwen3 (без --llm — офлайн-проверка)
.venv/bin/streamlit run ui/app.py                # http://localhost:8501, MCP-сервер стартует подпроцессом
```

Без Ollama:
- `python -m indexing.embed_index --embedder hash` строит индекс на лексической заглушке, только для проверки обвязки;
- поиск работает, а ответы LLM нет: интерфейс покажет понятную ошибку;
- если индекса Chroma нет, ретривер переходит на чистый BM25 и предупреждает об этом.

Дополнительно:

```bash
.venv/bin/python ask.py --demo --mermaid         # графовый путь без LLM, цепочки в Mermaid для слайдов
.venv/bin/python -m eval.run_eval --llm --no-graph --only 4 5 9   # сравнение для защиты: только вопросы-списки
.venv/bin/python -m eval.run_eval --llm --only 4 5 9 --router-cache  # отладка: 1–3 вопроса, без повторных вызовов маршрутизатора
.venv/bin/python -m indexing.extract_llm --mode classify            # извлечение графа классификацией пунктов (Ollama)
.venv/bin/python -m indexing.extract_llm --mode classify --reuse-raw --force   # пересчёт постобработки без модели
.venv/bin/python -m eval.eval_extraction --pred data/extracted/llm_classify     # мягкая и строгая метрики
.venv/bin/python -m eval.extraction_ceiling --docs all                        # потолок схемы (идеальные ответы)
.venv/bin/python -m indexing.extract_llm --mode free                # исходный свободный режим (базовая линия)
```

## Как устроено

```
вопрос -> rag/entities.py (банк, продукт, тип, термины, события)
       -> agent/router.py (Qwen3, JSON: rag | tool | both | refuse; аргументы проверяет код)
       -> agent/client.py -> mcp_server/server.py (FastMCP, stdio)   — расчёты
       -> вопрос-список («какие карты…», «по каким рассрочкам…»): rag/verdicts.py — таблицу выводов
          строит код по графу, модель пишет 1–3 предложения резюме, rag/prompt.py сверяет его с таблицей
       -> rag/retriever.py: vector_retriever (Chroma + BM25 + RRF) + graph_retriever (Kuzu)
       -> rag/prompt.py (фрагменты [c1], факты [f1], расчёты [t1]) -> Qwen3
       -> ответ «Плюсы / Минусы / Подводные камни / Итог» + блок «Источники» (собирает код)
```

| Путь | Что делает |

| `corpus/extra/*.md` | 6 памяток и 8 разборов кейсов (только векторный индекс) |
| `corpus/build_corpus.py` | YAML -> `data/raw/*.md`, `data/extracted/gold/*.json`, `data/catalog.json` |
| `indexing/schema.py` | схема графа, DDL, проверка связей |
| `indexing/chunk.py` | чанкинг по разделам, пункт договора не режется |
| `indexing/embed_index.py` | эмбеддинги через Ollama `/api/embed` -> Chroma |
| `indexing/build_graph.py` | gold/llm-разметка -> Kuzu |
| `indexing/extract_llm.py` | извлечение графа моделью: `--mode classify` (итоговый) или `--mode free` (базовая линия) |
| `indexing/classify_clauses.py` | классификация пунктов: перечисления в схеме Ollama, граф строит код, правила кода |

| `agent/` | маршрутизатор, MCP-клиент, агент |

| `eval/` | 20 вопросов, прогон, оценка экстракции (две метрики), потолок схемы |

| `docs/baseline.md` | базовая линия и замеры после доработок |

### Граф

Узлы: Bank, Product, Condition, Fee, Exception, Event, Term, Document.
Связи: OFFERED_BY, HAS_CONDITION, CHARGES, HAS_EXCEPTION, CANCELS, DEFINED_AS, SOURCE и два расширения:
- `TRIGGERS` (Event → Fee/Condition): пропуск платежа ничего не отменяет, а включает штраф или новую ставку;
- `APPLIES_TO` (Exception → Event): «снятие сверх 50 000 ₽ не входит в грейс» относится к превышению лимита, а не к снятию наличных.

У условия есть свойство `scope`: на какие события оно явно распространяется.
Например, у «100 дней» льготный период распространяется на снятие наличных и переводы. Без явного `scope`
вопрос-список отвечает «нет данных», а не «да». Это свойство, а не связь: набор связей эталона, а значит и метрики извлечения, не меняется.

У каждой связи есть `section`: пункт документа, где она написана. Поэтому ссылка ведёт
на «2.4. При пропуске платежа грейс отменяется», а не на «2.1. Льготный период — до 120 дней».

### Инструменты

Все расчёты детерминированные и выполняются кодом.
- `loan_calculator(sum, rate, months, type, fee)`: аннуитет `P = S·r / (1 − (1+r)^(−n))`, при `rate = 0` платёж `S/n`;
  для дифференцированных платежей переплата `S·r·(n+1)/2`.
- `grace_period_calc(purchase_date, statement_day, grace_days, mode)`: период из N дней включает дату старта,
  последний день = старт + N − 1. Режимы: `from_purchase`, `from_month_start` («Полярная 120»),
  `base_plus_extension` («Меридиан 150»: 60 + 90 дней).
- `compare_products(ids)`: таблица из графа по обслуживанию, снятию наличных, грейсу и кэшбэку.
- `save_summary(title, text)`: файл в `data/summaries/`; имя санитизируется, выйти из папки нельзя.

Параметры грейса берутся из каталога продукта, а не у модели. Числа для `loan_calculator`
обязаны встречаться в вопросе, иначе агент задаёт уточняющий вопрос.

### Маршрутизация и отказы

- Вопрос без слов предметной области и без чисел («какая погода завтра») отклоняется без вызова LLM.
- Банковская тема, которой нет в корпусе (вклады, ипотека), получает ответ «В корпусе нет данных по этому вопросу.»
- Остальное решает маршрутизатор. Расчётные вопросы без продуктов («кредит 100 000 ₽ под 18%») не отклоняются.
  Если маршрутизатор предлагает отказ, но в вопросе есть продукты, термины или числа, или если его ответ не разобран, агент откатывается на `rag`.

## Оценка

Все числа взяты из сохранённых прогонов (`review/`, `eval/results_*.json`). Подробности и базовая линия — в `docs/baseline.md`.

### Вопросы (`eval/questions.json`, 20 вопросов)

Проверяются обязательные факты, источники, маршрут, инструмент, числа и запреты `forbidden`: утверждения, которых не должно быть.
Проверки нечувствительны к форме слова. Результат делится на три части: маршрут, инструмент и числа; таблица (её строит код); текст модели.

| Прогон | Результат | Файл |
|---|---|---|
| Офлайн, эталонный маршрут, «ответ» = контекст | 20/20 | `eval/results_offline.json` |
| Qwen3 + граф, итоговый чистый прогон (коммит e78fec6) | **20/20**, в среднем 157 с на вопрос | `review/final_eval_llm.txt` |
| То же, резюме вопросов-списков сверено с таблицей | текст модели **18/20** (вопросы 4 и 5); ответ пользователя верный — таблицу строит код | `review/final_rescore_summary_check.txt` |
| Qwen3 + граф, вопросы 4, 5, 9 со сверкой резюме (коммит dcc83de) | таблица 3/3, текст модели 1/3: в вопросах 4 и 5 резюме отброшено и заменено собранным кодом; 21–27 с на вопрос | `review/final_eval_llm_459_summary_check.txt` |
| Qwen3 без графа, вопросы 4, 5, 9 | **0/3**: теряются 2–4 продукта из 5 | `review/final_eval_llm_nograph_459.txt` |
| Базовая линия: Qwen3 + граф, первый прогон | 13/20 | `review/eval_llm.txt` |
| Базовая линия: Qwen3 без графа | 13/20 | `review/eval_llm_nograph.txt` |

### Извлечение графа моделью

Режим `classify`: модель выбирает значения из перечислений для каждого пункта договора, граф строит код.

| | Мягкая F1 (исходная метрика) | Строгая F1 (тип, пункт, пункт/id) |
|---|---|---|
| Свободный режим, 4 продукта (базовая линия) | 0,37 | 0,41 |
| `classify` + правила кода, 4 продукта | 0,35 | 0,66 |
| `classify` + правила кода, все 20 продуктов | 0,37 | 0,64 |
| Потолок схемы `classify` (идеальные ответы), все 20 | 0,57 | 0,98 |

Порог ТЗ 0,7 не достигнут. По мягкой метрике он в этом режиме недостижим даже для идеальной модели: метрика сравнивает
придуманные человеком названия узлов, а код называет узлы по термину справочника. Поэтому демо идёт на эталонном графе из YAML.

## Риски

- **Качество LLM-экстракции — измерено, порог не достигнут.** Строгая F1 0,64 на 20 продуктах, мягкая 0,37 при пороге 0,7.
  Хуже всего связи CANCELS (0,24) и TRIGGERS (0,49): модель путает, что событие отменяет, а что влечёт.
  На свободных формулировках 0,56 против 0,67 на шаблонных. Для демо — эталонный граф из YAML.
- **Резюме модели может противоречить таблице** (вопросы 4 и 5 итогового прогона). Сверка в `rag/prompt.py` — эвристика
  по отрицаниям в частях фраз. Ошибку вида «у X проценты после двух пропусков» вместо «после одного» она не ловит.
  Таблица выводов показывается над текстом и остаётся главным ответом.
- **Скорость на CPU.** Видеокарты нет, в среднем 157 с на вопрос. Вопросы-списки — 45–107 с.
- **Запреты `forbidden` — эвристика.** Пара «продукт + слово» в одном предложении без «не/нет»; смешанные фразы она может пропустить.
- **3 фрагмента вместо 5** ускоряют ответ. Но без графа вопрос 13 теряет документ продукта: офлайн, `results_offline_nograph.json`.
- **Kuzu архивирован.** Версия закреплена (`kuzu==0.11.3`), весь Cypher изолирован в `rag/graph_store.py`.
- **Модель 7–8B и инструменты.** Поэтому инструментов 4, вместо function calling используется JSON-маршрутизатор с плоскими полями,
  а аргументы проверяет код.
- **Неоднозначность названий** (банк или продукт, «100 дней» или «за 100 дней»): правила в `rag/entities.py`, тесты в `tests/test_entities.py`.
- **Условия вымышлены.** В интерфейсе постоянная пометка, в каждом источнике дата редакции.
- **Названия программ лояльности** («Спасибо», «ЯРКО») и продукта «100 дней» взяты из постановки задачи.
  Если на защите они нежелательны, их можно переименовать в YAML и перегенерировать корпус одной командой.

## Проверка, что старых банков нет

```bash
# шаблон собран из кусков, чтобы команда не находила саму себя
old="пол""ярн|сир""ень|каш""тан|pol""ar|sir""en|kash""tan"
grep -rniIE "$old" . --exclude-dir=.venv --exclude-dir=chroma | grep -viE "пол""ярн(ая|ой|ую)( 1[^0]|[^ 0-9]| 120|$)"
```

Команда ничего не выводит. Допустимое совпадение — «Полярная 120», продукт банка «Северный Путь»; модель в ответах иногда сокращает его до «Полярной». Запрещены старый банк «Полярный» и продукт «Полярная 100».
Ту же проверку делает тест `tests/test_corpus.py::test_no_old_banks`.
