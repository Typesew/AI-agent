## Извлечение графа: классификация пунктов (`extract_llm --mode classify`)

Что измеряется. Модель получает один пункт договора и выбирает значения из перечислений: вид элемента, термин, событие, тип связи с событием, родительский пункт. Эталон и YAML модель не видит. Id, названия, значения и связи строит код и проверяет по схеме. Поверх ответов модели работают правила кода (отключаются флагом `--no-rules`):
- событие засчитывается, только если оно названо в пункте;
- дубли схлопываются;
- «не начисляется на / не распространяется на / не входят» превращает пункт в перечень исключений.

Две метрики (`eval/eval_extraction.py`):
- **мягкая** — исходная, не менялась. Сравнивает связи по похожести названий узлов;
- **строгая** — добавлена отдельно. Связь — это (тип, пункт-источник, пункт или id справочника у приёмника).

Выборка из 4 продуктов (balt_credit, sever_install, opora_debit, kedr_student):

| Вариант | Мягкая F1 | Строгая F1 | Время | Файл |
|---|---|---|---|---|
| Свободное извлечение (базовая линия) | 0,37 | 0,41 | ~18 мин на продукт | `eval_extraction_free_both_metrics.txt` |
| Классификация, промпт v1, без правил | 0,26 | 0,54 | 952 с на 4 продукта | `eval_extraction_classify_v1_norules.txt` |
| **Классификация, промпт v1 + правила** (итог) | **0,35** | **0,66** | те же ответы | `eval_extraction_classify_v1_rules.txt` |
| Классификация, промпт v2 (подсказки) + правила | 0,28 | 0,63 | 623 с | `eval_extraction_classify_v2_rules.txt` |
| Классификация, промпт v2 без правил | 0,27 | 0,61 | те же ответы | `eval_extraction_classify_v2_norules.txt` |
| Потолок схемы (идеальные ответы из эталона) | 0,51 | 0,98 | — | `extraction_ceiling_sample.txt` |

Все 20 продуктов (промпт v1 + правила), `final_eval_extraction_classify_all.txt`:
- мягкая F1 **0,37**, строгая F1 **0,64**; потолок схемы — 0,57 и 0,98 (`extraction_ceiling_all.txt`);
- по стилю (строгая): свободные формулировки 0,56, шаблонные 0,67;
- по типам связей (строгая): APPLIES_TO 0,79, HAS_CONDITION 0,69, HAS_EXCEPTION 0,69, DEFINED_AS 0,65, CHARGES 0,62, TRIGGERS 0,49, CANCELS 0,24;
- 150 пунктов, ни одного пропущенного, 1 связь отброшена проверкой схемы;
- 4 499 с на 130 новых пунктов: для 4 продуктов выборки ответы взяты из кэша. Это около 35 с на пункт.

Вывод. Порог 0,7 по мягкой метрике в режиме классификации недостижим даже для идеальной модели: потолок 0,51–0,57. Мягкая метрика сравнивает придуманные человеком названия узлов («Неустойка за просрочку»), а код называет узлы по термину справочника. Поэтому подгонять названия под эталон я не стал: это запрещено. Строгая метрика выросла с 0,41 до 0,64–0,66, но до 0,7 не дотянула. Для демо остаётся эталонный граф из YAML.

Где ошибается модель:
- **CANCELS и TRIGGERS:** путает, что событие отменяет, а что влечёт;
- **лишние элементы:** точность 0,53 при полноте 0,79;
- **свободные формулировки:** на них результат хуже, чем на шаблонных.

Подсказки-ключевые слова в промпте (v2) без правил кода помогают, а вместе с ними — нет. Модель сама отмечает исключения, но с неверным родительским пунктом.
